# 电动汽车充电桩应用管理平台

本仓库是一套充电桩运营系统。车主可以查找站点、预约、开始和停止充电并支付；运营人员可以查看订单、设备和告警。桩模拟器向服务端上报遥测，Web 大屏读取同一份业务库做展示。离线分析单独计算历史负荷、高峰和站点推荐，不改写正在进行的订单。

在线业务和离线分析使用不同的数据。订单、电桩状态和实时遥测来自统一的 SQLite 数据库 `runtime/charge_platform.sqlite`。历史负荷预测使用课程匿名小时数据，结果必须带数据版本和来源，不能把历史电量显示成当天营收。

## 系统组成

| 部分 | 位置 | 作用 |
| --- | --- | --- |
| C++ 服务端 | `server/` | 监听 `127.0.0.1:48080`，处理登录、订单、支付、告警和遥测，并写入统一 SQLite |
| Qt 车主端 | `clients/user/` | 登录、找站、预约、充电、支付和历史订单 |
| Qt 运营端 | `clients/admin/` | 运营查询、设备与订单查看、分析页面 |
| 桩模拟器 | `simulator/` | 按场景通过 TCP 上报遥测，覆盖正常充电、高温、离线、重复上报、时间或电量倒退等九类情况 |
| Web 大屏 | `dashboard/` | 默认打开第一阶段业务大屏；`?stage=2` 打开第二阶段分析页 |
| 在线分析接口 | `analytics/` | FastAPI 只读统一库，给第一阶段大屏提供 KPI、趋势、告警、推荐和场景切换 |
| 离线分析 | `bigdata/`、`analytics/` | Hive 报表、PySpark 特征、负荷模型，再由 Flask 提供预测、高峰、推荐和报表接口 |

金额和电量使用定点小数，不把浮点误差当作对账结果。预测样本不足时接口返回原因，不补造数值。课程小时数据没有容量和占用列，因此空闲桩预测保持为空，并标明 `NO_CAPACITY_DATA`，不用电量反推空闲桩。

## 已完成的内容

第一阶段把服务端、两个 Qt 客户端、桩模拟器和 Web 大屏接到同一 SQLite。大屏分为总览、态势、设备、运维四区，每 3 秒请求 `GET /api/dashboard`。顶栏出现 `SQLite已连接 · 3秒刷新` 时，表示读到的是统一业务库，而不是页面里写死的数字。场景切换会启动已构建的桩模拟器，遥测经 TCP 写入数据库后再反映到页面。

第二阶段在已发布的站点×小时数据上完成离线分析，链路是 Hive 报表和 PySpark 特征，然后训练负荷模型，最后由 Flask 只读接口提供给 Qt 和 Web。在本机课程数据 `course-local-v1` 上：

- Hive 分区表、日电量、小时负荷排名、站点覆盖率，以及 PySpark 特征，已经实际跑通。
- 1 小时、6 小时、24 小时负荷预测的测试误差低于昨日同小时基线。
- 高峰时段按未来 24 小时负荷取前三，预警表示相对历史高负荷，不控制设备。该项口径已按规格改写；未重新训练出 P90 阈值时，接口以降级状态返回。
- 站点推荐按距离、价格、当前可用比例和预测可用比例打分，不编造等待时间。预测可用比例仍因缺少容量数据而无法计算。
- 空闲桩预测保持阻塞，字段返回空值并说明原因。

上述第二阶段数字来自本机数据，不是另一份 `course-v1` 数据包。模型文件不进入仓库。分析服务停止时，预约、充电和支付仍由 C++ 服务端处理。

## 本地打开

先构建并启动 C++ 服务端，确认 `runtime/charge_platform.sqlite` 已存在，且 `127.0.0.1:48080` 正在监听。服务端未启动时，后面的脚本会失败，不会假装成功。

Windows 在项目根目录双击 `start-member3.bat`。脚本启动 FastAPI 和 Web 大屏，发送默认 `normal` 场景，并打开 `http://127.0.0.1:4173/`。结束时双击 `stop-member3.bat`。关掉启动窗口不会停止这两个进程，也不会停止 C++ 服务端或改动数据库。

Ubuntu 在项目根目录执行 `./start-member3.sh`。这条命令占用当前终端，Ctrl+C 会停止 FastAPI 和大屏。

两个页面：

- 第一阶段业务大屏：`http://127.0.0.1:4173/`
- 第二阶段分析页：`http://127.0.0.1:4173/?stage=2`

C++ 和 Qt 程序在配置构建目录并编译后，从 `build/` 下对应的可执行文件启动。数据库路径使用 `runtime/charge_platform.sqlite`。
