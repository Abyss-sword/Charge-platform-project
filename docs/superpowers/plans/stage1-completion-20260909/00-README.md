# 第一阶段剩余开发、三端联调与验收执行包

编制日期：2026-09-09。项目：`charge_platform_project`。本包供其他Agent实际开发使用，不是答辩稿，不采用“默认全部完成”的假设。

## 使用顺序

1. 所有执行者读 [审核与统一契约](01-review-and-contract.md)，先理解已知事实、安全边界和拟实施的契约。
2. 负责人按 [成员1实施计划](02-member1-plan.md) 完成公共入口与服务端改造；成员2、3分别读 [Qt双端计划](03-member2-plan.md)、[模拟器及数据大屏计划](04-member3-plan.md)。
3. 按 [集成与最终验收](05-integration-acceptance.md) 串联，必须在同一个候选提交上验收。
4. 将 [Agent提示词](06-agent-prompts.md) 中的总控提示词交给主Agent；确需并行时再分发对应角色提示词。

本轮交付的是说明与计划。没有执行这些新增功能，没有运行新一轮软件全量验收，也没有推送本包。旧文档保持原样；本包采用后，负责人才将其中的新约定同步进仓库的正式协议与baseline说明。

## 目标与停止条件

目标是可操作的车主端、运营端、桩模拟器、统一数据库和浅色Web大屏，完成正常充电支付及故障运维两条流程，并通过异常恢复检查。仅真实数据导入、治理、模型训练和真实数据性能留到第二阶段。

“可联调”“模块通过”“整组通过”“已推送”“已合并”“已部署”是不同状态，不能相互代替。

最终状态只有：

- `PASS`：第05文档全部必过项通过，同一候选版本，证据可复现。
- `FAIL`：已执行但存在阻断或错误，列明失败用例。
- `BLOCKED`：环境或权限等导致必要检查无法执行，写出具体所缺条件。

不承诺有限时间内必然全过；必须用门禁阻止不完整成果被标为完成。不得为赶9月10日验收删除需求、改低断言、把Mock改名为Remote或伪造通过记录。

## 文件与权限总则

- 本包默认只授权未来Agent在**新隔离候选分支**开发、测试和本地提交，不授权推送、合并main、部署到旧演示目录或操作已有运行库；这些步骤要单独获得用户同意。
- 不修改成员原功能分支；候选分支汇入已固定提交后再按文件归属修改。保留原分支作为可恢复来源。
- 不使用 `git reset --hard`、`git clean -fdx`、强推、全目录覆盖、批量杀进程；不自动stash用户修改。
- 使用apply_patch修改源码与文档；工具生成物遵守各自输出目录。禁止用新实现覆盖整仓库。
- 不读出/上传SSH私钥、口令、令牌、真实身份信息；不把运行库和账号配置提交进Git。环境变量检查只报告“存在/缺失”，不打印值。
- 新数据库放在候选工作树内专用测试目录或系统临时目录。任何重置都要先验证绝对路径属于该目录，确认无进程使用，保留备份；正式演示期间禁止重置。
- 一份文件同一时间一名写作者。根CMake、shared、数据库迁移和正式协议仅成员1/总控写。
- 一次失败后先读日志定位；同一认证/网络错误连续出现不循环重试、不改全局SSH配置。请求必要授权，不泄露凭据。
- 不安装大型组件、不更改系统服务/防火墙/全局Git和SSH设置来绕开局部问题。
