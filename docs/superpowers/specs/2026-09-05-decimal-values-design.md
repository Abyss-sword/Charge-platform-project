# 金额与电量十进制两位化设计

日期：2026-09-05
状态：已确认方案，待实施计划与代码实现
负责人：成员1

## 1. 目标

将项目当前以整数“分”和整数“Wh”为核心的金额、电量模型，调整为面向业务的十进制模型：金额统一使用“元”，电量统一使用“kWh”，单价统一使用“元/kWh”。数据库、服务、协议、数据导出和测试使用一致的单位与命名。

所有金额、电量、单价和余额在进入可持久化业务状态前，统一按十进制四舍五入规则保留两位小数。例如：

- `10.2705` 元变为 `10.27` 元；
- `10.2750` 元变为 `10.28` 元；
- `8.344` kWh变为 `8.34` kWh；
- `8.345` kWh变为 `8.35` kWh。

本次修改不使用C++普通二进制浮点数承担金额运算，也不使用SQLite `REAL`保存金额，以避免累计误差。

## 2. 方案选择

采用方案A：使用Boost.Multiprecision提供的高精度十进制类型完成解析、乘法、比较和四舍五入；数据库使用规范的两位十进制文本保存；网络协议使用十进制字符串传输。

Ubuntu当前缺少Boost头文件，实施前安装`libboost-dev`。该计算组件只使用头文件，不增加运行时动态库部署步骤。GitHub自动构建环境后续也必须安装同一依赖。

不采用以下方案：

- 不使用`double`与SQLite `REAL`保存金额，避免`0.1 + 0.2`一类二进制浮点误差。
- 不继续把领域接口暴露为`amountCents`、`energyWh`等整数单位。

## 3. 统一业务规则

### 3.1 字段与单位

| 旧字段 | 新字段 | 新单位 | 协议示例 |
| --- | --- | --- | --- |
| `balanceCents` | `balanceYuan` | 元 | `"100.00"` |
| `priceCentsPerKwh` | `priceYuanPerKwh` | 元/kWh | `"1.23"` |
| `energyWh` | `energyKwh` | kWh | `"8.35"` |
| `amountCents` | `amountYuan` | 元 | `"10.27"` |

数据库字段同步改为`balance_yuan`、`price_yuan_per_kwh`、`energy_kwh`、`amount_yuan`。新字段保存规范化文本，必须带两位小数。

### 3.2 输入规则

- API只接受普通十进制字符串，不接受科学计数法、`NaN`、无穷值、空字符串或混合单位。
- 金额、电量和单价不得为负；资金流水中的支出允许由服务端生成负值，客户端不得自行提交负充值。
- 输入可以超过两位小数，但服务端必须在验证后立即按四舍五入规则规范为两位。
- 规范化后的累计电量不得小于订单当前累计电量。
- 所有协议输出固定包含两位小数，禁止用JSON数字传输，以免丢失末尾的零。

### 3.3 计算顺序

1. 遥测累计电量先转成kWh并四舍五入为两位。
2. 站点单价在创建或修改时四舍五入为两位。
3. 停止充电时，以已固化的两位电量乘以两位单价。
4. 乘积使用高精度十进制完成，再四舍五入为两位订单金额。
5. 支付、充值、退款、余额与营收只处理已规范化的两位十进制值。
6. 重复支付继续复用原请求结果，不重新计算或再次扣款。

示例：`8.35 kWh × 1.23元/kWh = 10.2705元`，订单最终金额为`10.27元`。

对正数和负数都采用通常意义上的四舍五入：绝对值第三位为5时远离零。例如`-10.275`规范为`-10.28`，用于资金流水中的支出记录。

## 4. 代码边界

在`shared/domain/`增加统一十进制值对象，集中负责：

- 严格解析十进制字符串；
- 检查范围和符号；
- 四舍五入到两位；
- 固定两位格式化；
- 精确比较、加减和乘法；
- 与SQLite文本字段、Qt JSON字符串之间转换。

业务服务、仓库结构和网络路由不得各自实现不同的格式化函数。所有金额与电量必须经过该统一对象，避免模块间规则不一致。
