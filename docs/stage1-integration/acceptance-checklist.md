# 第一阶段三端联动验收清单

## 1. 验收前准备

- [ ] 记录成员1、成员2、成员3和集成分支提交号。
- [ ] 确认工作树没有意外未跟踪文件。
- [ ] 重置唯一模拟数据库并确认种子数量。
- [ ] 启动C++服务端、Qt车主端、Qt运营端、桩模拟器、FastAPI和Web大屏。
- [ ] 确认各程序使用同一个数据库配置和互不冲突的端口。
- [ ] 所有界面显示`SIMULATED`。

## 2. 正常业务闭环

- [ ] 车主端使用固定手机号登录。
- [ ] 登录后显示数据库中的用户和余额。
- [ ] 查询附近站点并进入站点详情。
- [ ] 选择空闲电桩并预约。
- [ ] 运营端刷新后看到新订单和电桩占用状态。
- [ ] 车主端开始充电。
- [ ] 模拟器向同一电桩发送递增遥测。
- [ ] 车主端显示更新后的电量、费用和时间。
- [ ] Web大屏显示负荷、充电订单和在线设备变化。
- [ ] 车主端停止充电并进入结算。
- [ ] 金额、电量和单价均显示两位小数。
- [ ] 用户完成模拟支付，余额实际减少。
- [ ] 运营端看到订单完成和营收增加。
- [ ] Web大屏在3秒内显示更新后的订单和营收。
- [ ] 充电记录中能够查询刚完成的订单。

## 3. 异常与一致性

- [ ] 两个用户同时预约同一电桩，只允许一个成功。
- [ ] 重复点击支付只扣款一次。
- [ ] 余额不足时支付失败且数据库不产生成功流水。
- [ ] 禁用电桩后车主端不能预约。
- [ ] Qt断线时显示明确状态，不能把旧数据标为实时。
- [ ] 写操作超时后通过查询恢复权威状态。
- [ ] 重新启动车主端后恢复活动订单或历史记录。
- [ ] FastAPI停止时，登录、预约、充电和支付仍可运行。

## 4. 告警和工单闭环

- [ ] 模拟器发送超过70℃的合法遥测。
- [ ] 服务端只生成一条有效高温告警，重复上报不制造告警风暴。
- [ ] 运营端能够查询并确认告警。
- [ ] 工单能够从待处理进入处理中、已解决和已关闭。
- [ ] 操作日志记录管理员、对象、动作和时间。
- [ ] Web大屏显示告警及处置后的状态变化。

## 5. 页面完整性

车主端必须可操作：

- [ ] 登录、首页、附近站点、站点详情、导航降级、预约确认。
- [ ] 充电状态、活动订单恢复、结算、账户、充值和充电记录。

运营端必须可操作：

- [ ] 管理员登录、概览、营收、站点、电桩、订单和用户。
- [ ] 告警、工单和操作日志。

Web大屏必须显示：

- [ ] 数据来源、核心指标、负荷曲线、站点排行。
- [ ] 告警、推荐、数据质量、更新时间和失败状态。

```bash
cmake --build build
ctest --test-dir build --output-on-failure

cd analytics

cd ..
git diff --check

```

通过条件：构建和测试无失败；完整正常流程和告警流程各连续通过两遍；没有错误扣款、状态分叉、未标记模拟数据或严重界面缺失。

## 7. 验收结论

只有全部阻断项清零，才能标记第一阶段通过。允许保留到第二阶段的内容仅限真实数据导入、数据治理、模型训练优化、预测推荐完善和真实数据性能验证。
