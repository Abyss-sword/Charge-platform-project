# 第一阶段统一架构与规则

## 1. 数据流

```text
Qt车主端 ── TCP/JSON ──┐
Qt运营端 ── TCP/JSON ──┤
桩模拟器 ── TCP/JSON ──┼── C++服务端 ── SQLite模拟业务库
                       │
Web大屏 ── HTTP ── FastAPI只读服务 ── SQLite只读连接或服务端只读接口
```

## 2. 唯一业务事实来源

- SQLite模拟业务库是用户、余额、站点、电桩、订单、支付、遥测、告警、工单和操作日志的唯一事实来源。
- Qt端、模拟器和Web大屏不得各自维护另一套权威业务状态。
- 所有写操作必须经过成员1的C++服务端。
- FastAPI和Web大屏只读业务事实，不得直接修改订单、余额、电桩、告警或工单。
- 固定JSON可以保留为离线演示夹具，但只有显式进入`OFFLINE_DEMO`模式时才能使用，不能在正常模式静默回退。

## 3. 通信边界

### Qt车主端和运营端

- 使用现有4字节网络字节序长度头和JSON正文。
- 每个请求具有唯一`requestId`、`version`、`action`和`payload`。
- 响应必须按`requestId`匹配到发起请求。
- 连接断开时页面显示“服务断开”，不能把旧数据显示为实时数据。
- 写操作超时后必须查询权威状态，不能直接重复提交支付。

### 充电桩模拟器

- 使用同一TCP帧格式。
- 上报动作统一为`PILE_TELEMETRY`。
- 电桩编号必须能映射到SQLite中的正整数`pileId`。
- 遥测包含`recordedAt`、`temperatureC`、`voltageV`、`currentA`、`powerW`和`energyKwh`。

### Web大屏

- 浏览器不直接连接SQLite或普通TCP端口。
- 第一阶段采用FastAPI HTTP接口加2～3秒轮询，减少临时引入新通信层的风险。
- FastAPI从同一SQLite模拟数据库读取运营汇总数据。
- 如课程明确要求浏览器使用Socket，再在第二个变更中增加FastAPI WebSocket推送；不得因此延误基本联动。

## 4. 数据库规则

- 数据库路径只能通过统一配置提供，禁止三个成员分别硬编码不同数据库文件。
- 演示数据库必须有可重复的重置方式。
- 重置只允许在演练开始前执行，正式演示过程中禁止重置。
- 金额、余额、单价和电量使用高精度十进制语义，数据库和协议输出固定两位字符串。
- 示例：`10.2705→10.27`，`10.275→10.28`，`8.345→8.35`。
- 时间使用带时区的ISO 8601字符串。

## 5. 第一阶段与第二阶段边界

第一阶段完成：

- 全部主要页面和按钮；
- 模拟数据库驱动的业务操作；
- TCP通信；
- 三端联动；
- 模拟遥测、告警和工单；
- Web运营数据同步；
- 错误、断线和恢复。

第二阶段完成：

- 合法数据来源登记；
- 匿名真实或公开聚合数据导入；
- 字段映射和单位转换；
- 清洗、拒绝、质量和回算；
- 模型训练、基线比较、预测和推荐；
- 真实数据下的性能与降级验证。

第二阶段不得通过重做数据库或页面来绕过第一阶段未完成项。

## 6. 目录所有权

| 成员 | 单写目录 |
| --- | --- |
| 成员1 | `server/`、`shared/`、`database/`、公共脚本和根构建文件 |
| 成员2 | `clients/user/`、`clients/admin/`、`clients/shared/ui/`、`tests/ui/` |
| 成员3 | `simulator/`、`analytics/`、`dashboard/`及其测试 |

共享协议和数据库字段由成员1冻结。成员2、3发现缺口时更新协议差异表，不直接创造同义字段或第二套状态。
