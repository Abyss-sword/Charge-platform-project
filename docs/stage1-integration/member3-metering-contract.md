# 成员3累计电表与订单计量契约

更新日期：2026-09-09  
实现状态：代码、迁移、单元测试和真实TCP集成测试已落地；等待成员1书面确认。

## 1. 字段语义

`PILE_TELEMETRY.energyKwh`表示电桩生命周期累计电表读数，单位为kWh，使用普通十进制文本传输和保存。它不是当前订单用电量，FastAPI也不会用该值直接覆盖订单。

同一电桩的有效数据必须同时满足：

- 时间戳为带时区的ISO 8601时间；
- 新时间不早于最近一次已接受时间；
- 新累计电量不小于最近一次已接受读数；
- `pileId`存在于统一数据库；
- 模拟数据明确保存`source_mode=SIMULATED`；
- 客户端收到服务端成功响应后才计入`ACKNOWLEDGED_FRAMES`。

## 2. 订单换算规则

订单开始时，服务端读取该桩最近一次累计电表并保存到`charge_order.meter_start_kwh`。充电中的订单电量按下式更新：

```text
订单电量 = 当前有效累计读数 - 订单起始累计读数
```

如果订单开始时尚无遥测，第一条有效读数只建立起始基线，订单电量为`0.00`；下一条有效读数再计算差值。

订单停止后不再接受遥测对订单电量或已结算金额的修改。下一笔订单重新读取最近有效累计电表，建立新的起始基线。

## 3. 幂等和异常边界

- 相同`pile_id + recorded_at + energy_kwh`视为精确重复：返回成功并标记`duplicate=true`，不新增遥测、不重复更新订单、不重复计费。
- 同一时间但读数或其他遥测值不同：拒绝为`TELEMETRY_OUT_OF_ORDER`。
- 时间倒退或累计电量倒退：拒绝为`TELEMETRY_OUT_OF_ORDER`。
- 未知电桩：拒绝为`PARAM_INVALID`，不写入脏数据。
- 高温达到70℃：复用同一活动告警和工单，不重复创建。
- 超过15秒无心跳：服务端离线监测将电桩置为`OFFLINE`；恢复合法上报后按活动订单恢复`CHARGING`，否则恢复`IDLE`。
- 设备真实换表或归零不伪装成普通遥测；必须先由成员1提供受控换表操作或人工确认新基线，本阶段默认拒绝电量倒退。

## 4. 兼容入口

`ORDER_TELEMETRY`暂时仅作为旧客户端兼容入口保留。新模拟器统一调用`PILE_TELEMETRY`，订单计量只由服务端根据活动订单和电表基线计算；成员3分析服务始终只读数据库。
