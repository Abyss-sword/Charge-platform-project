# 成员2第一阶段Qt双端联动任务

## 目标

把当前Qt界面预览升级为真正操作模拟数据库的车主端和运营端。页面设计继续复用，但正常模式不得继续使用固定业务卡片代替接口结果。

## 共用Socket客户端

- [ ] 在`clients/shared/`或两端共用层实现`ServiceClient`。
- [ ] 实现连接、4字节长度头、JSON收发、`requestId`匹配、超时和断线通知。
- [ ] 一个响应只能完成对应请求，不能按返回顺序猜测页面。
- [ ] 断线时保留最后数据但明确标记“已过期”，写操作按钮禁用。
- [ ] 重连后重新查询用户、活动订单和当前页面数据。
- [ ] `MockDataProvider`只保留为显式`OFFLINE_DEMO`模式，不能在请求失败后静默伪造成功。

## 9月7日：登录和查询链路

- [ ] 增加车主登录页，完成手机号校验、等待、成功和错误提示。
- [ ] 保存服务端返回的`userId`，退出后清除会话。
- [ ] 首页和账户页读取用户资料及余额。
- [ ] 附近站点页调用`STATION_NEARBY`。
- [ ] 站点详情页调用`STATION_DETAIL`并显示数据库中的电桩状态。
- [ ] 增加管理员登录页并保存`adminToken`。

当日门禁：两个Qt程序均通过Socket登录；车主端显示数据库余额和站点；运营端完成管理员鉴权。

## 9月8日：车主端完整功能

- [ ] 预约确认调用`ORDER_RESERVE`，成功后进入活动订单。
- [ ] 取消预约调用`ORDER_CANCEL`。
- [ ] 开始充电调用`ORDER_START`。
- [ ] 充电页定时调用`ORDER_DETAIL`，显示数据库中的电量、单价、费用和更新时间。
- [ ] 停止充电调用`ORDER_STOP`并进入结算。
- [ ] 充值调用`WALLET_RECHARGE`，随后重新查询余额。
- [ ] 支付调用`WALLET_PAY`；按钮等待期间不可重复点击。
- [ ] 支付超时后先查询订单状态，不直接重发。
- [ ] 活动订单页调用`ORDER_ACTIVE`，重启客户端后可以恢复。
- [ ] 充电记录页调用`ORDER_HISTORY`。
- [ ] 覆盖余额不足、桩被占用、订单状态冲突、服务断开和参数错误。

## 9月8日：运营端完整功能

- [ ] 概览、营收、站点、电桩、订单、用户和日志页面接入相应`ADMIN_*`查询。
- [ ] 站点新增和修改调用正式管理动作。
- [ ] 电桩启用、停用和模拟重启调用正式管理动作。
- [ ] 用户冻结和解冻调用`ADMIN_USER_FREEZE`。
- [ ] 告警页面查询并调用`ADMIN_ALARM_ACK`。
- [ ] 工单页面查询并调用开始、解决和关闭动作。
- [ ] 操作完成后重新查询，不能只修改本地表格。
- [ ] 每个页面至少具备加载、正常、空数据、错误和断线状态。

当日门禁：车主端完成登录到支付；运营端能看到同一订单、余额变化、营收和告警。
