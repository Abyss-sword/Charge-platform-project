## 1. 这份手册解决什么问题

你负责Qt车主端、Qt运营端和两端共用界面能力。第一阶段必须完成全部窗口、导航、视觉样式、通用状态和模拟业务展示；第二阶段不重新设计页面，而是在原页面上切换正式数据、补齐推荐、故障、恢复和降级逻辑。

完成工作的判断标准不是“窗口已经画出来”，而是：用户能按固定路径完成操作，加载/正常/空数据/失败/断线或降级状态能够触发，界面字段与服务端一致，规定分辨率不裁切，关闭动效后功能不变，并由非作者复跑。

### 1.1 如何像上实训课一样使用本手册

每个工作日按下面五步学习与执行，不要直接跳到代码：

1. **先说清目的。** 开始前用自己的话回答“今天解决哪个用户问题、为什么必须今天完成”。说不清就重新阅读当日目标。
2. **先认输入。** 检查协议、字段、模拟数据和前一日证据。输入未冻结时不要猜字段，更不要把猜测写进页面。
3. **先观察失败。** 测试必须先因“今天的能力尚不存在”而失败；如果是编译环境、旧代码或路径问题，先排除这些问题。
4. **分层完成。** 按“可到达的页面骨架→正确字段→完整状态→真实交互→统一样式→适量动效”的顺序做。前一层未通过，不进入下一层。
5. **让别人复现。** 结束前把程序交给非作者，自己只提供操作入口，不提示正确答案。对方能按证据独立复现才算完成。

每做完一个复选框，立即在当天证据文件中写一行实际结果。不要等到晚上凭记忆补记录。

## 4. 固定设计规则

### 4.1 色彩

| 含义 | 色值 | 界面用途 |
| --- | --- | --- |
| 品牌深海蓝 | `#102F46` | 顶栏、运营侧栏、一级标题 |
| 操作蓝 | `#3478C5` | 链接、次按钮、选中项、信息状态 |
| 充电绿 | `#24AD7A` | 主按钮、在线、空闲、成功、实际负荷 |
| 能源青 | `#32B9C8` | 图表辅助、实时状态和渐变端点 |
| 活力绿 | `#82C75B` | 正向趋势和低风险提示 |
| 琥珀色 | `#EDA14B` | 警告、待确认、即将超时 |
| 珊瑚红 | `#DF6B65` | 故障、失败、危险操作、严重告警 |
| 数据紫 | `#756FC5` | 预测与模型结果 |
| 页面浅灰 | `#F3F7F9` | 内容区背景 |
| 卡片白 | `#FFFFFF` | 卡片、表格和弹窗 |
| 正文深灰蓝 | `#183044` | 正文和关键数值 |
| 次要文字灰 | `#6B7B88` | 单位、时间和说明 |

状态必须同时包含图标或文字，不能只变颜色。

### 4.2 尺寸

- 车主端基准480×1040，最小360×780；使用C++17和Qt Widgets在Ubuntu桌面模拟手机App的纵向体验，不使用Android、QML或Qt Quick。采用PageHeader＋QStackedWidget＋底部固定五项导航，内容单列、纵向、卡片式、可垂直滚动，保持现有11类业务页面和业务流程。
- 运营端基准1360×820，最小1180×720。
- 基础间距4px，常用8/12/16/20/24px。
- 输入框与按钮圆角8px，卡片10～12px，主行动卡14～16px。
- 正文13～14px，辅助文字不得小于11px。
- 同一页面强主按钮不超过两个。
- 车主端使用Layout与QScrollArea，不依赖绝对坐标。360×780下顶部关键操作、底部导航和滚动区外的主操作完整可见，状态可读；允许次要信息换行及非关键说明折叠，不允许核心业务依赖横向滚动、导航文字裁切或机械压缩桌面双栏。

### 4.3 动效

- 页面进入220～350ms，只播放一次。
- 卡片依次进入，相邻延迟60～80ms，总时长不超过500ms。
- 数字变化300～500ms。
- 按钮反馈150～200ms。
- 状态颜色变化180～250ms。
- `ui/animations=false` 时直接显示最终状态。
- 禁止持续闪烁、背景粒子、动画阻塞点击或业务请求。
