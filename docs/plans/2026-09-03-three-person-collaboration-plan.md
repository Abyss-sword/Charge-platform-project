## 2. 每日统一操作流程

每天都按下面顺序执行。其他模型或 Agent 也必须遵守。

1. 09:00检查主线构建和前一日测试。失败时先恢复主线，不领取新任务。
2. 09:15短会只确认四项：当日唯一目标、允许修改的文件、依赖版本、验收命令。
3. 09:30各成员创建独立分支。命名为 `feature/dNN-short-name`，一个分支只交付一个可验证结果。
4. 开发顺序固定为：写失败测试，确认失败原因，写最小实现，运行相关测试，再运行受影响的主线回归。
5. 15:30进入集成窗口。先合并协议和服务端，再合并模拟器，最后合并客户端或大屏。
6. 16:30由非作者复跑。复核者不得只看截图，必须执行命令或按完整操作路径重现。
7. 17:15当日主负责人更新 `docs/evidence/day-N.md`。内容包括提交号、命令、通过数量、失败项、接口变化和次日依赖。
8. 17:30冻结当天结果。阻断或严重缺陷未清除时，不开始次日的新功能。

周末9月5～6日、12～13日只做预检，每人每天不超过4小时。允许准备固定输入、异常样例和文档；不允许引入新功能、修改冻结协议或把周末结果直接标为验收通过。
