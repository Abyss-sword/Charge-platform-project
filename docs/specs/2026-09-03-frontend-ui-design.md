# 电动汽车充电桩应用管理平台前端界面设计规格

**日期：** 2026年9月3日
**适用项目：** charge_platform_project
**设计状态：** 用户已确认，作为实施与验收基线
**覆盖范围：** Qt车主端、Qt运营端、浅色Web运营大屏

## 1. 设计目标

前端采用“清洁能源品牌感＋企业级运营工作台”的组合方向。车主端强调可信、直观和主流程清晰；运营端强调信息密度、筛选效率和风险处置；Web大屏保持浅色背景，以适应教室投影和普通显示器。三端共享品牌、颜色、状态、字号和交互规则，避免呈现为三个互不相关的课程作业。

本规格不新增或删减业务功能，只定义已有功能应如何组织、显示、反馈和验收。

## 2. 两阶段实施边界

### 2.1 第一阶段：9月9日完成内部验收，9月10日正式验收

第一阶段必须完成本规格中的全部主要窗口、导航、组件和状态。业务数据允许由统一模拟数据提供器产生，但必须满足以下要求：

- 页面不得留白、保留未完成提示或用无意义占位框代替。
- 模拟数据统一标记为 `SIMULATED`，页面能显示数据时间。
- 车主端可演示登录、找站、详情、导航降级、预约、充电、结算、充值和个人中心。
- 运营端可演示概览、营收、设备、站点、订单、用户、告警、工单和操作日志。
- Web大屏可演示指标、负荷、排行、分流建议、告警和数据质量区域。
- 每个主要页面至少具备加载、正常、空数据和失败状态；涉及网络或外部服务的页面还要具备断线或降级状态。

### 2.2 第二阶段：9月16日完成内部验收，9月17日全量验收

第二阶段不得重新设计导航或重做第一阶段页面。开发重点是把统一数据适配器从模拟数据切换到 `REAL_ANONYMIZED` 或 `PUBLIC_AGGREGATED`，并补齐数据治理、预测、推荐、回算、恢复和性能逻辑。

切换后应保持：

- 页面结构、字段位置和主要操作不变。
- 数据模式、数据集版本、覆盖时间和更新时间清晰可见。
- 分析服务不可用时，基础充电流程仍能运行。
- 模型不可用或没有可靠优势时显示“基线估计”，不能伪装为模型预测。
- 真实匿名数据、公开聚合数据和模拟数据不能使用含糊标签。

## 3. 统一视觉语言

### 3.1 品牌与气质

产品名称在界面中统一使用 `EV FLOW`，中文场景名分别为“充电服务”“运营中心”和“城市充电运营态势”。整体气质应接近成熟新能源服务产品：清洁、可靠、温和但不幼稚，信息丰富但不拥挤。

Logo暂用文字标识，不在14天内增加复杂图形Logo设计任务。

### 3.2 色彩系统

| 用途 | 色值 | 使用规则 |
| --- | --- | --- |
| 品牌深海蓝 | `#102F46` | 顶栏、侧栏、一级标题、关键文字 |
| 操作蓝 | `#3478C5` | 链接、次级按钮、选中项和信息状态 |
| 充电绿 | `#24AD7A` | 主按钮、空闲/在线/成功状态、实际负荷 |
| 能源青 | `#32B9C8` | 图表辅助系列、渐变端点、实时状态 |
| 活力绿 | `#82C75B` | 正向趋势、低风险辅助状态 |
| 琥珀色 | `#EDA14B` | 警告、待确认、即将超时 |
| 珊瑚红 | `#DF6B65` | 故障、失败、危险操作、严重告警 |
| 数据紫 | `#756FC5` | 预测曲线、模型结果和对比数据 |
| 页面浅灰 | `#F3F7F9` | Qt内容区和Web大屏背景 |
| 卡片白 | `#FFFFFF` | 卡片、表格、弹窗和筛选区 |
| 正文深灰蓝 | `#183044` | 正文和数值 |
| 次要文字灰 | `#6B7B88` | 辅助说明、更新时间、单位 |
| 边框灰 | `#DCE6EC` | 卡片、输入框、分割线 |

颜色不能作为唯一状态表达。所有状态同时包含图标或文字，例如“● 在线”“△ 待确认”“× 故障”。

### 3.3 渐变规则

渐变只用于品牌文字、车主端主行动卡片、重点图表面积和少量选中状态：

- 品牌渐变：`#102F46 → #3478C5 → #24AD7A`。
- 车主端主卡片：`#102F46 → #1C5773`，文字使用白色。
- 绿色图表面积：`rgba(36,173,122,.38) → rgba(50,185,200,.04)`。
- 成功卡片：`#EEF9F5 → #FFFFFF`。
- 告警卡片：`#FFF4ED → #FFFAFA`。

禁止大面积高饱和渐变、紫色霓虹背景和影响文字识别的玻璃效果。

### 3.4 字体与数字

- Qt端中文优先使用系统可用的“思源黑体”“Noto Sans CJK SC”或“微软雅黑”，找不到时回退到Qt系统无衬线字体。
- Web端优先使用本地字体栈，不依赖外网字体。
- 一级页面标题：20～24px，粗体。
- 二级模块标题：16～18px，中粗体。
- 正文：13～14px。
- 辅助说明：11～12px，不得小于11px。
- Web大屏关键数字：24～34px；图表标题：14～16px。
- 金额、功率、电量、时间和百分比使用等宽数字特性，单位不得省略。

### 3.5 间距、圆角与阴影

- 基础间距单位为4px，常用间距为8、12、16、20、24px。
- 输入框和按钮圆角8px，普通卡片10～12px，主视觉卡片14～16px。
- 卡片只使用轻阴影；默认边框必须保留，避免投影时卡片边界消失。
- Qt窗口最小内容边距16px，Web大屏内容边距16～24px。
- 同一页面主要操作按钮不超过两个，危险操作不得与主操作紧邻。

## 4. 动效与反馈

### 4.1 允许的动效

| 场景 | 动效 | 时长和触发 |
| --- | --- | --- |
| 页面进入 | 淡入并上移8～12px | 220～350ms，只播放一次 |
| 卡片加载 | 分组依次淡入 | 相邻延迟60～80ms，总时长不超过500ms |
| 数字指标 | 从旧值平滑过渡到新值 | 300～500ms，数据更新时触发 |
| 图表 | 曲线绘制、柱条增长 | 400～700ms，首次加载或筛选后触发 |
| 按钮 | 悬停提亮、按下缩小1%～2% | 150～200ms |
| 在线状态 | 小圆点轻缓呼吸 | 2秒循环，仅在线提示 |
| 状态变化 | 标签颜色淡变、文字同步替换 | 180～250ms |
| 页面切换 | 内容区淡出再淡入 | 160～220ms，不移动导航栏 |

### 4.2 禁止的动效

- 不使用持续闪烁、跑马灯、背景粒子或大面积光效。
- 告警不通过快速闪烁吸引注意，改用颜色、图标、声音开关和未读数量。
- 不让动画阻止点击，也不等待动画完成后才发出业务请求。
- 低性能、远程桌面或测试模式可通过配置关闭全部非必要动画。

### 4.3 操作反馈

- 请求发出后立即显示加载状态，并禁用会导致重复提交的按钮。
- 成功反馈说明“完成了什么”，例如“支付成功，订单已完成”。
- 失败反馈说明“哪里失败、数据是否保存、下一步能做什么”。
- 表单错误显示在对应字段下方，不只弹出统一对话框。
- 长操作超过8秒时显示仍在处理中，并保留取消或返回入口。
- 删除、冻结、停止充电、远程重启等操作必须二次确认，并显示对象名称或编号。

## 5. 共用组件

三端虽然技术不同，但视觉含义保持一致。

| 组件 | 内容 | 必须支持的状态 |
| --- | --- | --- |
| 顶部品牌栏 / 车主端PageHeader | 产品名、当前区域或用户、连接状态；车主端按页面需要显示标题、返回和必要状态，不固定堆叠全部信息 | 正常、断线、重连中、降级 |
| 侧栏/底部导航 | 图标、名称、选中态、未读数 | 默认、悬停、选中、禁用 |
| 数据模式标签 | 模式、版本、覆盖时间、更新时间 | 模拟、真实匿名、公开聚合、过期 |
| 指标卡 | 名称、数值、单位、趋势、口径 | 加载、正常、无数据、异常 |
| 状态标签 | 图标、状态文字 | 在线、空闲、占用、充电、离线、故障等 |
| 筛选条 | 时间、站点、状态、关键词、重置 | 默认、已筛选、无结果 |
| 数据表格 | 表头、排序、分页、操作列 | 加载、正常、空数据、失败 |
| 空状态 | 简短原因、下一步操作 | 首次无数据、筛选无结果、权限不足 |
| 错误提示 | 原因、影响、重试或降级按钮 | 网络失败、服务错误、权限错误 |
| 确认弹窗 | 操作对象、影响、确认/取消 | 普通确认、危险确认、执行中 |
| Toast通知 | 结果摘要 | 成功、信息、警告、失败 |

`MockDataProvider`与正式接口必须返回相同的界面视图模型，页面不得分别维护两套字段解释。

## 6. Qt车主端

### 6.1 整体结构

车主端定位为“使用Qt Widgets在Ubuntu桌面环境中模拟手机App使用体验的纵向客户端”，采用C++17和Qt Widgets，不改为Android，不使用QML或Qt Quick。基准窗口尺寸为480×1040，最小尺寸360×780。本次仅调整车主端UI信息架构与布局，客户端/服务端架构、协议、业务流程、成员职责和现有11类业务页面保持不变。

整体采用紧凑顶部PageHeader、中央QStackedWidget内容区、底部固定五项导航，不使用固定左侧导航：

```text
QMainWindow
└── centralWidget
    └── QVBoxLayout
        ├── TopBar / PageHeader
        ├── QStackedWidget（当前业务页面）
        └── BottomNavigationBar
```

底部导航顺序固定为：首页 / 找桩 / 订单 / 记录 / 我的，分别对应首页、附近站点、活动订单、充电记录、我的账户。使用QFrame或QWidget配合QHBoxLayout、QToolButton，图标在上、短文字在下；当前项除颜色外还须有选中标记或形状变化。底部只承载五个一级入口，不排列全部11类页面。

站点详情、导航/降级、预约确认、充电状态、活动订单恢复处理和结算通过页面入口、返回按钮或业务流程跳转到达。底部“订单”沿用现有活动订单页面作为入口，恢复处理不新增页面类别或底部项。PageHeader按页面需要显示返回按钮、标题、定位、必要连接状态和页面操作；首页可展示品牌与当前位置，连接异常必须明确提示。

车主端内容采用触控友好的单列、纵向、卡片式布局，可用QScrollArea垂直滚动；使用QVBoxLayout、QHBoxLayout，QGridLayout仅用于局部小型信息，不主要依赖setGeometry()、move()或固定绝对坐标。

在360×780下，PageHeader关键操作和底部五项导航须完整可见，主操作按钮放在滚动内容之外的页面操作区，状态信息须可读且不得被遮挡。完整内容可垂直滚动查看，核心业务不得依赖横向滚动。允许卡片纵向排列、次要信息换行、非关键说明折叠；不得裁切导航文字或关键按钮、缩小字体到规格下限以下，或将桌面双栏机械压缩到窄屏。以上车主端规则不应用于运营端。

当用户存在 `RESERVED`、`CHARGING` 或 `PENDING_PAYMENT` 订单时，页面内容顶部显示醒目的活动订单摘要卡，并提供唯一主操作“继续处理”。

### 6.2 登录页

布局：品牌介绍、充电场景渐变卡片和手机号登录表单按单列上下排列，内容较多时垂直滚动，登录主操作保持可见。

组件：Logo文字、产品说明、手机号输入框、登录按钮、教学模拟提示、连接状态、隐私说明。

交互：手机号输入时仅保留数字，格式错误就地提示；登录中按钮显示加载并禁用；首次登录成功提示已创建教学账户；服务断开时保留输入内容并显示重试。

验收：空值、非法号码、新用户、已有用户、冻结用户、服务断线六种状态均可展示。

### 6.3 首页

首页使用QScrollArea承载纵向卡片，优先显示欢迎语与当前位置、连接状态、附近可用站点摘要、存在时的活动订单摘要和深海蓝渐变找站主卡；随后纵向排列余额/订单/最近站点三个快捷卡、推荐站点列表、数据模式与更新时间。附近可用站点摘要复用已有站点信息，不增加业务能力。

首页只保留一个强主按钮“查找附近充电站”。推荐卡显示站名、距离、价格、空闲数、快慢充和拥堵提示。

第一阶段推荐来自固定规则和模拟数据；第二阶段显示推荐理由与数据模式。分析不可用时仍按距离和空闲数排序，并显示“当前使用基础排序”。

### 6.4 附近站点页

顶部筛选：模拟位置/实际位置、距离范围、快慢充、价格区间、仅看有空闲桩、排序方式。主体采用“列表 / 地图”模式切换，默认显示纵向站点卡片列表；地图或位置预览在同一内容区切换显示，不新增业务页面。筛选控件允许换行或纵向排列，切换模式保留筛选条件与所选站点。地图不可用时该区域改为纵向地址、坐标和区域站点排行卡片，仍可返回列表，不采用左列表＋右地图双栏。

站点卡显示距离、空闲/总桩、最低单价、营业状态和导航按钮。筛选无结果时提供“清除筛选”。

### 6.5 站点详情页

采用纵向信息卡片，依次显示站名、地址、营业状态、总空闲数、导航和收藏/最近访问标记、价格与服务说明及电桩列表。

电桩使用窄屏卡片显示编号、快慢充、额定功率、当前状态、预计可用时间和主操作，信息允许换行。故障、离线或占用桩不能出现可用的预约按钮。

### 6.6 导航页与降级页

正常状态用 `QWebEngineView` 显示路线，并在页面上方保留起点、终点和出行方式。地图失败时不显示空白Web视图，改为降级卡片：站点地址、经纬度、复制地址、返回站点详情和继续预约。

### 6.7 预约确认页

采用单列确认摘要布局，依次显示站点、电桩、功率、单价、预约有效期和取消规则。主按钮为“确认预约”，次按钮为“返回选择”。并发占桩失败时说明该桩已被占用，并给出“查看其他空闲桩”。

### 6.8 充电状态页

采用纵向卡片布局，核心区域使用环形或横向进度表现当前状态，关键数字为功率、电量、时长和预估费用。下方展示桩编号、订单编号、连接状态与最近更新时间。

“停止充电”使用琥珀色边框按钮并二次确认。断线时保留最后一次数值，明确标记“数据可能已过期”，重连后以服务端状态覆盖本地显示。

### 6.9 活动订单恢复页

登录后发现未完成订单时自动进入。根据预约中、充电中、待支付分别展示倒计时、实时充电或结算主操作。页面不提供创建新订单入口。

### 6.10 结算页

采用纵向账单摘要和独立主支付操作区，顶部显示“充电已结束”，中部逐行展示电量、时长、固化单价、服务费、应付金额和余额。金额使用分隔清晰的大号数字。余额不足时提供模拟充值入口；支付中禁止重复提交；成功后展示订单完成编号和返回首页按钮。

### 6.11 我的账户页

采用移动端个人中心式纵向布局，包含头像占位、昵称、脱敏手机号、账户状态、余额、模拟充值、订单历史和退出登录。充值使用预设金额＋自定义金额，不展示真实支付渠道标识。冻结用户看到限制说明，但仍能进入活动订单和结算。

### 6.12 充电记录页

顶部提供可换行的状态和时间筛选，主体采用纵向记录卡片列表，不使用宽屏表格，按时间倒序显示站点、桩号、电量、时长、金额和订单状态。点击记录在当前页面展开纵向详情，展示计费明细和状态时间线，可收起并返回记录列表位置。没有历史订单时显示首次充电引导；查询失败时保留筛选条件并提供重试。

## 7. Qt运营端

### 7.1 整体结构

建议窗口基准尺寸为1360×820，最小尺寸1180×720。左侧深海蓝导航固定宽度180～208px；顶部显示页面标题、区域、系统连接状态、当前管理员；内容区使用浅灰背景。

导航顺序：运营概览、营收分析、站点资产、电桩设备、充电订单、用户管理、告警工单、操作日志。

### 7.2 管理员登录页

采用居中或左右分栏登录卡。必须显示当前连接环境和“教学系统”说明。失败时区分账号错误、权限不足和服务不可用，不显示内部错误堆栈。

### 7.3 运营概览页

第一行五张指标卡：今日营收、服务车次、平均利用率、设备在线率、未处理告警。不同卡可使用绿、蓝、紫、青和珊瑚红辅助色，但数值文字统一深色。

第二行：近24小时负荷或营收趋势、设备状态分布、最新告警。第三行：高负荷站点和快捷工单入口。

第一阶段显示模拟口径；第二阶段增加数据模式和覆盖时间。营收仅统计已完成订单，并在帮助提示中说明。

### 7.4 营收分析页

顶部为7日/30日切换、日期范围和站点筛选；中部为趋势图、订单量与客单价卡；下部为订单明细表。图表和表格必须使用同一筛选条件，并显示当前统计口径。

### 7.5 站点资产页

左侧或上方为筛选，主体为站点表格。字段包括站点名、区域、总桩、空闲、故障、利用率、状态和操作。新增/编辑使用右侧抽屉或对话框，字段错误就地显示。

进入详情后展示站内电桩、地址坐标、价格和近期利用率，不另建无必要的独立导航层级。

### 7.6 电桩设备页

顶部状态筛选与桩号搜索；表格显示桩号、站点、类型、功率、状态、心跳时间、温度和操作。状态标签必须同时使用图标与文字。

远程重启为危险操作：确认框显示桩号、站点和当前故障；执行中禁止关闭重复提交；超时后保留原告警并提示转人工处置。

### 7.7 充电订单页

筛选项包含订单号、用户、站点、状态和时间范围。表格显示订单状态、电量、时长、金额、创建/完成时间。详情采用抽屉展示状态时间线、支付流水和异常说明。

### 7.8 用户管理页

手机号默认脱敏。列表显示昵称、脱敏手机号、余额、账户状态、注册时间。冻结/解冻要求填写原因并二次确认。冻结后状态标签、可执行操作和说明必须立即同步。

### 7.9 告警工单页

页面采用“告警列表＋工单详情”双栏结构。左侧可按严重度、状态、站点和时间筛选；右侧显示设备摘要、告警时间线、处置记录、远程重启结果和关闭说明。

严重度使用珊瑚红、琥珀色和操作蓝区分，同时显示“严重/警告/提示”。未选择告警时显示操作引导，不显示空白区域。

### 7.10 操作日志页

提供操作者、动作、对象、结果和时间筛选。敏感字段脱敏，不显示密码、密钥或完整手机号。详情显示可理解的业务摘要，不直接展示难以解释的原始内部结构。

## 8. 浅色Web运营大屏

### 8.1 显示与布局

主要适配1920×1080和1366×768，页面允许纵向滚动但首屏必须包含核心指标、负荷趋势和告警。背景使用浅灰或极浅青灰渐变，卡片使用白色；不使用深色主题作为验收默认方案。

顶部栏固定显示产品名、区域、数据模式、数据集版本和更新时间。数据过期时标签改为琥珀色，并明确显示“数据已超过更新周期”。

### 8.2 首屏区域

1. 五项核心指标：累计电量、服务车次、营收、设备在线率、未处理告警。
2. 24小时实际负荷与下一小时预测。
3. 站点利用率排行。
4. 最新告警事件流。

指标卡依次使用绿色、蓝色、紫色、青色和珊瑚红辅助装饰；卡片主体仍保持白色和深色文字。

### 8.3 第二屏区域

1. 可解释分流建议：站点、预计等待时间、距离、空闲数和推荐理由。
2. 数据质量与来源：raw、有效、拒绝、有效率、批次和来源许可摘要。
3. 设备状态分布和站点负荷对比。
4. 模型与基线说明：当前采用的结果、评测时间范围和降级状态。

### 8.4 大屏状态

- 加载中：保留完整布局，以骨架屏表示卡片和图表。
- 模拟数据：顶部显示绿色边框的 `SIMULATED` 标签和“教学模拟数据”。
- 真实匿名数据：显示 `REAL_ANONYMIZED`、版本与覆盖时间。
- 公开聚合数据：显示 `PUBLIC_AGGREGATED`、来源和许可摘要。
- 空数据：说明当前筛选无记录，保留来源和筛选条件。
- 接口失败：保留最近一次成功数据并标记时间；没有缓存时显示重试，不出现白屏。
- 模型失败：实际数据继续展示，预测区域改为基线估计或明确不可用。
- 地图失败：用站点排行和区域摘要替代，不影响其他区域。

## 9. 页面导航与业务流

### 9.1 车主端主流程

`登录 → 首页 → 附近站点 → 站点详情 → 预约确认 → 充电状态 → 结算 → 订单完成`

导航、地图和分析属于增强环节，任一不可用都不能阻断预约、充电和结算的模拟业务闭环。

### 9.2 运营端处置流程

`运营概览 → 告警列表 → 工单详情 → 确认告警 → 远程重启或填写处置 → 验证恢复 → 关闭工单 → 操作日志`

页面必须让验收人员能看到每一步的状态变化，不能只在数据库或日志中证明。

### 9.3 多端联动

完成一笔充电后：车主端订单完成，运营端营收和订单更新，大屏服务车次与电量更新。注入超温后：运营端出现告警和工单，大屏未处理告警增加。第二阶段的历史分析指标必须与实时业务指标通过数据模式标签区分。

## 10. Qt实现约束

- 使用Qt Widgets和QSS，不引入新的重量级UI框架。
- 两个Qt端共用颜色、字号、按钮、输入框、标签、表格和弹窗QSS变量。
- 页面只消费视图模型和服务代理，不直接解析Socket或访问数据库。
- 图标优先使用项目内SVG资源，必须统一线宽和视觉尺寸。
- 动效优先采用 `QPropertyAnimation`，只对透明度、位置、颜色或进度值做短动画。
- 表格大数据量时使用分页或限制返回数量，不通过一次加载全部记录解决。
- 页面切换时，车主端保留PageHeader和底部导航，运营端保留侧栏和顶栏，避免每次重建整个主窗口。

建议资源位置：

```text
clients/shared/ui/
├─ theme.h
├─ theme.cpp
├─ common.qss
├─ widgets/
└─ icons/

clients/user/pages/
clients/admin/pages/
```

## 11. Web实现约束

- 使用Vue 3、Vite和ECharts，不为本项目增加新的UI组件库。
- 色彩、间距和动画时长用CSS变量统一定义。
- 图表数据、来源信息和错误状态由统一适配层处理，组件不得自行伪造回退数据。
- 默认采用定时查询；不因视觉效果引入WebSocket强实时依赖。
- 所有动画尊重 `prefers-reduced-motion`，测试模式可关闭动画。
- 1366×768下不得出现核心指标被横向裁切；1920×1080下避免空白过多。

建议资源位置：

```text
dashboard/src/
├─ styles/tokens.css
├─ styles/motion.css
├─ components/common/
├─ components/charts/
├─ views/OverviewView.vue
└─ adapters/dashboardDataAdapter.ts
```

## 14. 已确认的设计决策

1. 采用A与B结合的商业化设计方向。
2. Qt车主端为480×1040基准、360×780最小的纵向Qt Widgets桌面客户端，采用PageHeader、中央页面栈、底部五项导航和清洁能源品牌型纵向卡片布局。
3. Qt运营端使用企业级侧栏工作台布局。
4. Web大屏保持浅色背景，不使用深色默认主题。
5. 允许适量增加辅助色、渐变、数字和文字动效。
6. 动效必须克制、可关闭，不得影响业务和测试。
7. 第一阶段完成全部界面并使用模拟数据，第二阶段复用界面接入真实匿名或公开聚合数据。
