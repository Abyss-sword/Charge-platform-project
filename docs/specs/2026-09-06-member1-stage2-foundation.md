# 成员1第二阶段可提前建设基础规格

## 目标与边界

本工作包不依赖真实数据，使用固定模拟输入完成设备遥测、离线判断、告警与工单服务端基础。真实或公开数据的来源许可、清洗质量、模型指标和最终回算仍在数据到位后验收。

## 当前契约

- 活动业务协议为TCP/JSON v2，金额、电量和单价均使用普通十进制字符串。
- 数据库通过004迁移保存固定两位文本：元、kWh、元/kWh。
- 分析出口为 `charge_event_v2`；v1仅作历史参考。
- 服务端计算统一使用 `DecimalValue`，禁止恢复整数分/Wh或二进制浮点金额计算。

## 遥测规则

- 遥测必须引用已存在的充电桩，时间有效且不早于该桩上一条遥测。
- 累计电量 `energy_kwh` 必须为规范的非负两位十进制，且不得倒退。
- 温度、电压、电流必须为有限数；功率不得为负。
- 接受遥测后按服务端接收时间更新 `last_heartbeat_at`；设备上报时间单独用于遥测排序和防倒退。高温阈值默认70°C，可由构造参数覆盖，便于测试和后续配置化。
- 离线扫描由服务端单一周期任务每5秒调用；最后心跳距当前时间至少15秒的非离线桩转为 `OFFLINE`。
- 心跳恢复或高温恢复为正常遥测时先查询活动订单：预约中恢复为 `RESERVED`，充电或待支付恢复为 `CHARGING`，没有活动订单才恢复为 `IDLE`。

## 告警与工单规则

- 高温和离线均创建告警；同一桩、同一类型、状态为 `OPEN` 或 `ACKNOWLEDGED` 时只保留一条活动告警。
- 创建告警时同时创建工单，两项在同一数据库事务内成功或回滚。
- 旧库升级保留全部历史告警；若存在重复活动告警，仅关闭较早重复项并同步关闭其工单，保留最新一条活动项，再为缺失工单的告警补建工单。
- 告警状态：`OPEN → ACKNOWLEDGED → CLOSED`。
- 工单状态：`OPEN → PROCESSING → RESOLVED → CLOSED`。
- 工单关闭前必须已经恢复、处于 `RESOLVED`，且处理说明非空；关闭工单时同步关闭告警。
- 操作日志记录处理人、动作、对象、结果和时间。

## 第一批验收用例

1. 正常遥测写入并刷新心跳。
2. 未知桩、非法数值、时间倒退和累计电量倒退被拒绝，数据库无部分写入。
3. 高温遥测原子创建一条告警和一张工单；重复高温不重复创建。
4. 超过15秒未心跳的桩变为离线并产生告警/工单。
5. 设备恢复时不会覆盖活动订单对应的桩状态。
6. 告警与工单状态只能按规定顺序推进；未恢复或说明为空时不能关闭。
